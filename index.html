01这条线跑多久，是算出来的

一帧图像多久传完，不是随手给的。它由四件事定死：分辨率 × 数据格式决定每行多少字节； lane 数决定每条线摊到多少，也就决定了一个包有多长；HBlank / VBlank决定行周期和帧周期； 时钟 lane 频率决定比特率，也就是传输速度。

上面那排数字就是这套推导的结果。改任何一个，整条波形的长度都会跟着变。 注意 CSI-2 里没有消隐波形这回事——并行接口在消隐期有专门的电平，而这里消隐期就是链路挂在 LP-11 上干等， 所以消隐值唯一的效果是把空白段拉宽。

动手：把时钟 lane 从 50 MHz 调到 400 MHz，帧率上限从 35 跳到 277，但波形结构一点没变。 变的只是每一行在链路上跑完的快慢——这就是为什么配参时带宽算高了纯属白烧功耗。

02帧的两头：两个短包

帧起始和帧结束都是短包，只有四个字节：数据标识、帧号、校验。 它们不传图像，只负责告诉接收端“新的一帧开始了”和“这帧完了”。

短包短到什么程度？几百纳秒。在一帧几毫秒的尺度里，它细得像根头发。 但少了它，接收端就不知道该怎么把后面那几百行长包拼成一张完整的图。

动手：点“帧起始”，再往上滚两格，能看到四个字段被细线分开。

03一行数据：长包

长包比短包多两样东西：两字节的字长，和末尾两字节的校验。中间那段就是这一行的像素数据。

一个长包完整的一生是这样的：从 LP-11 里出来，先握手，再稳定，再同步，然后一口气把数据推完， 收尾，回到 LP-11。包与包之间必须回到 LP-11，这是协议规定的，不能包挨着包连着发。

动手：点“一行”，整包的结构一次看全，上面的色带标了每个阶段。行越长，实心块越宽——一千多个字节挤在几十微秒里，缩着看就是这么一块。

04发数据前得先握手

要从 1.2V 的单端信号切到 200mV 的差分信号，不能悄悄切过去。所以先拉成 LP-01，停一段最短 50ns； 再拉到 LP-00，再停一段。

这两拍的意思很直白：第一拍说“注意，我要提速了”，第二拍说“我准备好了，你把接收机打开”。 接收端必须在这点时间里完成终端电阻切换和共模电压建立，所以这两个下限写死在规范里。

动手：点上面的“一行”，把光标停在 burst 开头，读数会告诉你此刻是 LP-01 还是 LP-00。

05稳定期为什么这么长

进了高速也不急着发数据，先要把差分硬拉成 0，保持至少 105 纳秒再加 12 个比特时间。 看着像浪费，其实是给驱动器偏置和线路反射留安顿的时间。

接收端会一直盯着这根线，等它连续 8 个比特都是 0 才认定“稳了”，然后开始找同步头。

动手：这段稳定期每一个包前面都有，一千多行就是重复一千多遍。 包越短，这笔固定开销占的比例越高，所以真实的图像传感器能用长行就用长行。

06同步头：八个零后面那串

稳定期之后是固定的一串：00011101。 连同前面一路的 0 一起，接收端看到的是一长串 0 突然变成 0-0-0-1-1-1-0-1，这个跳变就是字节边界的锚点。

为什么不干脆用全 1？因为连续的 0 之后那个上跳最难认错。 接收端的状态机会拿这 8 位跟固定图案比对，对不上就报同步错误、整包扔掉——这是抓波形最常见的故障之一。

动手：跳到同步头，紫色那块底子就是它，上面标了每一位的 0 和 1。

07低速那条路

数据发完了，有时候还得往回说点话，比如读寄存器。方向反了，走不了高速通道。 办法是回到 LP-11 之后拉成 LP-10 作为入口，绕一圈进逃逸模式。

逃逸里每一位用一整段低功耗状态表示：1 用 LP-01，0 用 LP-00，每位 50 纳秒。 慢得像老牛拉车，但只占 Dp 一根线的高低，功耗极低，而且能反向跑。

动手：勾上“带一段逃逸”，波形尾部会多出一小段，点“逃逸”跳过去。

08拿探头去测，容易踩的坑

第一个坑是只看一个包。帧级的问题——比如帧间隙太短导致丢帧、行数对不上——在几微秒的时基里永远看不出来， 必须把时基拉到毫秒级，让整帧缩成一片栅栏。

第二个坑是垂直量程。二百毫伏的差分摆幅放在零点几伏的量程里就是一条粗线，怎么调都看不清。 要么拉开水平缩放，要么换差分探头。

第三个坑是只调比特率不看消隐。把时钟 lane 拉高一倍，帧率上去了， 但只要 VBlank 也跟着翻倍，帧率会原样掉回来。带宽预算里这两个数是乘在一起的，缺一不可。

第四个坑是地线。探头那根黑夹子太长形成环路，量出来的边沿全是振铃—— 你以为是芯片驱动能力差，其实是探头自己接进来的噪声。测这种信号，地弹簧比探头本身还重要。

关键时序参数

每个包固定要付的开销，数值取自 D-PHY 1.x 的公开下限。不同版本和不同厂商会在这个基础上加码， 实际配参请以你手上芯片的收发器手册为准。

参数这一段是什么下限
T-LPX低功耗状态的最短持续时间50 ns
T-HS-PREPARELP-00 到差分拉 0 之间的准备时间40 ns + 4 UI
T-HS-ZERO差分保持 0 的稳定期，接收端靠它锁相105 ns + 12 UI
T-HS-TRAIL最后一个比特之后的收尾保持60 ns + 4 UI
T-HS-EXIT回到 LP-11 后继续等待的时间100 ns
UI一个比特的时间，等于速率的倒数由速率决定
T-HS-SETTLE从 LP-00 到差分稳定之间，接收端滤掉的那一段由接收端能力决定

上面这些是每个包都要付的固定开销，和载荷多少无关。所以行越长，这笔开销摊得越薄。

整条线的时长怎么来的

每行字节      = ceil(宽 × bit每像素 / 8) + 6
每 lane 字节  = ceil(每行字节 / lane 数)
一行传输      = 每 lane 字节 × 8 / 比特率 + 包开销
行周期        = 一行传输 × (宽 + HBlank) / 宽
帧周期        = 行周期 × (高 + VBlank)
帧率上限      = 1 / 帧周期

最后一行的“上限”两个字是关键：这套推导假设链路一刻不停地跑，算出来的是这条链路最高能跑到多少帧。 真实配置会留两到三倍余量，所以同样的分辨率，实际帧率通常比这个数字低不少。

页面里的电平是理想化画法，省掉了上升下降时间、过冲和抖动。真实探头看到的边沿有圆角， 稳定期里还有肉眼看不见的噪声——那些才是调试时真正要盯的东西。

波形长度是从传感器配置算出来的，不是估的。但页面里的消隐值只用来拉长行周期和帧周期， 真实的消隐时序还牵扯到传感器的内部流水线，配参仍以芯片手册为准。
